## 仅迁登录的隔离演练

[迁移程序](migrate_login.py) 只接受 SQLite 源版本 `d4c1a8e37b62` 与目标版本 `9f6c2a8d1b43`。在停止写入的旧服务上导出到受保护目录，再导入目标版初始化的空库。旧服务如用环境自定义权限，传入其管理员接口 `GET /api/v1/users/default/permissions/defaults` 得到的布尔权限树。数据库保存的显式设置优先。账号、验证哈希、准入角色、禁用标记、外部主体及组权限按白名单处理。新建会话戳，新增五项权限默认关闭。遇到旧版授予、目标已移除的 `features.direct_tool_servers` 时，停止并报告需要对应适配的授权差异。

```text
python downstream/migrate_login.py export --source OLD_DB --bundle PRIVATE_BUNDLE --source-defaults OLD_DEFAULT_PERMISSIONS_JSON
python downstream/migrate_login.py import --bundle PRIVATE_BUNDLE --target NEW_DB
python -m unittest discover -s downstream/tests -p test_login_migration.py
```

使用候选 wheel 的真实 Alembic 迁移建立源库和目标库。合成管理员与成员使用原密码重登。OIDC 关闭自动注册和按邮箱合并后，通过独立回环提供方的授权码流程回到同一成员 ID。待批账号无法访问聊天，禁用账号被拒。登录接口回读并核对实例默认权限、组授权及新增权限。旧库含聊天与文件，导入后、重建实例配置前，目标的 47 张业务表均为空。旧 Core 数据、外部存储和真实账号均未用于此演练。

九项 SQLite 回归覆盖重复导入、中断恢复、冲突、重复标识、历史数值型 OAuth 主体、已占用的目标库、旧权限和导出文件保护。[迁移测试](tests/test_login_migration.py)

复跑安装演练时，使用待测 wheel 所在的专用 Python 环境，向下列入口传入已提交的 Dissipative 候选、受保护的主题材料及 Playwright 驱动。每次生成独立的合成库、两轮模式截图和汇总。演练使用回环端口 18476、18477、18479。[演练入口](tests/rehearse_install.py) · [浏览器断言](tests/upgrade-appearance.mjs)

```text
python downstream/tests/rehearse_install.py --wheel WHEEL --output PRIVATE_TEMP --core-source DISSIPATIVE_CHECKOUT --theme-source VERSIONED_THEME_DIR --theme-function REVIEWED_FUNCTION_PY --browser-runner PLAYWRIGHT_PW_MJS
```

## 组合资格

### Schema 34 客户端

Adapter 4.22 在 WebUI 进程设置 `DISSIPATIVE_CONTINUITY=1`、`DISSIPATIVE_INSTANCE_ID`、`DISSIPATIVE_LOOPBACK_URL` 和 `DISSIPATIVE_API_KEY_FILE` 后启用。实例密钥须持有本实例的 `memory:read` 和 `memory:write`。本次重启演练使用 `DISSIPATIVE_STARTUP_SYNC=1`、`DISSIPATIVE_LIVENESS_SYNC=0`，以便单独观察启动回读。WebUI 迁移 `d59b632a4c18` 在所属聊天保存服务端版本账本，登录迁移仍只复制准入信息。聊天内容、模型凭据与实例密钥均不写入版本账本。

从空数据库启动专用 Core，使用 `--api-key-registry`、`--curator model`、`--curator-scheduling-protocol 4`、`--model-invocation-profile qwen-custom@2`，并依次启用 `--enable-continuity-transport`、`--enable-round-curation`、`--enable-profile-selection`、`--enable-profile-publication`、`--enable-source-format-transition`。Core 将独立连接绑定为 `qwen-continuity@1`，从其进程的 `DISSIPATIVE_MODEL_ENDPOINT`、`DISSIPATIVE_MODEL_MODEL`、`DISSIPATIVE_MODEL_API_KEY` 加载。FAST Reader 另启用 `--enable-retrieval-fast-first-release`。旧 managed catalog 有独立启动模式。普通聊天继续使用 WebUI 的模型连接。

Filter、Event 和 Tool 使用原有插件 ID。后端在已认证聊天所属行上串行保留来源版本，按活动分支同步，使用 Core 返回的消息 ID。完成轮从归档入口登记，明确点击 HUD 的 **Curate completed messages** 才提交增量整理。**Check progress** 用同一请求查询回执；Profile 选择提交预期版本。服务重启重放来源并核对归档。字段发布、来源生命周期和 FAST 发布分别按对应合同核验。[客户端实现](../backend/open_webui/utils/dissipative_continuity.py) · [组合演练](tests/qualify_continuity.py)

在 Dissipative 导出提交 `0da9380` 运行 `python scripts/test.py --all`，12 组确定性门禁通过。Integrations 的 506 项中有一项按条件跳过，Profiles 的 1,014 项全部通过。该运行使用工作树内的临时库，Git 限本地文件协议。[Dissipative 候选记录](https://github.com/harrywenjie/dissipative/blob/codex/open-webui-upgrade-20261121/docs/DEVELOPMENT.md)
